# 絵理香K版 アペンド（追記）の本文入力方式 — 史料照合メモ

作成日: 2026-10-14
対象: `apps/server/internal/hostprogram/erikak/runtime.go` の `append_body` / `new_body`（現状はいずれも 1 行入力で確定）

## 1. 問題の所在（現状）

- 新規投稿（`new_body`）もアペンド（`append_body`）も、入力 1 行を受けた時点で確定する。空行は中止。
- `..` を終端とする入力は `chat.go:290` にのみ存在し（チャットルーム退出）、掲示板の本文入力には使っていない。
- 「ピリオド 2 つで終わる複数行入力」を裏づける記述は、現時点でリポジトリ内のどの史料・文書にも見つかっていない。

## 3. 確認できたこと / 確認できていないこと

**確認済み（史料で直接見える）**
- 誰かが実際にアペンドを書いた例がある。`APPEND 板 記事` の行が付くブロックは、本文のあと親記事（板 6 の記事 N）へのアペンドとして記録されている（B-00032、1993 年 4 月の複数ブロック）。
- アペンドは親記事の下の子として並び、件名を持たない（既存メモ `ERIKA_K_BOARD_MENU_COMMANDS.md` と整合）。
- そのアペンド本文は、空行を挟んだ複数段落を持つものがある（B-00032）。

**推定（強いが、史料だけでは確定しない）**
- `A` コマンドで対象を指定したあと、本文を入力して確定する流れ。`APPEND 板 記事` の行は、その確定結果の記録と読める。ただし、入力のエコーか保存記録かは未確定。
- 複数段落の本文が残っていることから、入力も複数行だった可能性が高い。

**未確認（史料に記録がない）**
- 入力画面のプロンプト文字列（`A` のあとに出る行）。史料の `-->` 行は、数字入力か空行しか見当たらない。
- 終端記号（`..` / `.` など）の有無。
- 複数行入力が、どの行で確定したか（空行か、終端記号か）。

なお、前回までの「アペンドを誰かがした例は見つからない」という整理は誤りでした。既存記事への表示ではなく、ブロック末尾の `APPEND` 行を見落としていました。

## 4. 実装への扱い

- 史料で入力方式が確定するまで、現状（1 行入力）を変えない。
- 根拠が見つかれば、`append_body` と `new_body` の両方を、終端記号が来るまで行を溜める形に揃える。その際、どの終端記号かも史料に基づいて決める。
- 推測で `..` を終端にすることは避ける。
