# Spec 017: チャット室での住民の発言 (chat-utterances)

## 1. 概要

spec 016 で、住民はチャット室に出入りするようになったが、話さない。本仕様で、チャット室の住民が話すようにする。

- **誰が・いつ・何に対して話すかは World が決定論的に決める。** LLM は、World が選んだ 1 行を言葉にするだけ（`AGENTS.md`、`docs/LLM_POLICY.md`）。
- **本文を作るのは、人間が同じ部屋にいる間だけ。** そこで住民同士の会話も本文を作る（上限つき）。人間がいない部屋の発言は観測されない事実であり、作らない。
- **黙ることは正しい結果。** 人間の発言に、住民が必ず応じるわけではない。LLM の失敗や検証の不合格も、その住民が黙ったことになる。決まり文句の代わりの本文は作らない。

本仕様も 2 層からなる（spec 016 と同じ分け方）。

- **共通の方針（ホストプログラムに依らない）。** 発言の枠の決定、本文の生成、記録、上限。世界とインフラの層に置く。
- **絵理香K版での具現化。** 部屋の住民の発言を、接続記録の発言の行の形（`HANDLE  :本文`）で、入退室の行と時刻順に混ぜて出す。

## 2. 背景と課題

1. **部屋の住民が話さない。** spec 016 の `ChatEvents`（`worldrepo/callplan.go:142`）は入退室だけを返し、絵理香K版の `roomEvents`
   （`erikak/chat.go:297`）はそれだけを出す。人間が話しても、誰も応じない。
2. **人間の発言は記録されているが、住民の発言の型がない。** `world.ChatUtterance`（`world/chat.go:26`）には、どの発言に応じたか、
   World のどの決定から来たかを持つ欄がない。
3. **LLM で 1 行を作る経路がない。** 既存の生成は掲示板の記事（`llm.BoardPostRenderer`）で、記事の題・本文・字数の考え方に縛られている。
   チャットの 1 行には別の狭いインターフェースが要る。
4. **反応の選択（spec 008）は未実装。** 掲示板での住民の反応の選び方はまだない。本仕様は、チャット室での選び方を自分で定める
   （spec 008 と同じ考え方: World がサンプリングし、LLM は言葉にする）。
5. **関係の情報。** 2 人の関係は、掲示板の返信の数（`RelationshipEdge.BoardReplyCount`）からだけ求まる（spec 013）。
   チャットの発言は関係を更新しない。本仕様は既存の関係を読むだけにする（§8）。

## 3. 決定事項

- spec 016 §3 の決定をそのまま引き継ぐ。特に: 人間が同じ部屋にいるときは住民同士の会話も本文を作る（上限つき）。
  LLM の設定がないとき、住民はチャット室に入らない（したがって話さない）。方針は汎用で、絵理香K版はその具現化。
  回線数・部屋の数・定員は局の定義から決まる。
- 世界の基準の年は世界ごとに決まる（PR #355 のコメント）。本仕様の文面・検証は「世界の日付」を入力として受け取り、1996 年を定数にしない。
- 本文の生成に使う LLM の呼び出しは、既存の構造化出力（JSON スキーマ）の経路を使う。

## 4. ユーザーストーリー

1. **部屋で会話が聞こえる（共通 + 絵理香K版）。** テレホタイムに、住民が 2 人以上いる部屋 0 に入って黙って待つと、住民同士の発言が
   `HANDLE  :本文` の形で、入退室の行と時刻順に流れる。
   - 独立したテスト: 試験用の生成器（決まった 1 行を返す）で、決まった世界時刻と住民の部屋に入り、世界時刻を進めると、
     発言の行と入退室の行が時刻順に出て、各発言の時刻にその話者が部屋にいる。
2. **話しかけると、ときどき応じる（共通）。** 人間が発言すると、部屋の住民のうち多くとも 1 人が、少し間をおいて応じることがある。
   ハンドルを呼ばれた住民は応じやすい。応じないこともある。
   - 独立したテスト: 多数の発言で、1 発言あたりの応答者が 1 人以下、ハンドルを含む発言で呼ばれた住民の応答率が含まない発言より高い、
     応答のない発言がある。
3. **同じ時刻の同じ事実（共通）。** 一度表示した発言は変わらない。同じ世界・同じ人間の行動なら、どの住民がいつ何に応じて話すか（枠）は同じになる。
   - 独立したテスト: 同じ入力で枠を 2 回計算すると同じ。記録した発言は、後から住民を追加しても、もう一度問い合わせても変わらない。
4. **人間がいない部屋の発言は作らない（共通）。** 人間がいない部屋、人間が入る前、人間が出た後の時刻について、生成器は呼ばれない。
   - 独立したテスト: 人間が部屋にいない状態で `ChatEvents` を呼んでも、生成器の呼び出しが 0 回。
5. **うるさくならない（共通）。** 1 部屋の住民の発言は、決めた上限（§5 FR-005）を超えない。
   - 独立したテスト: 住民の多い部屋に 1 時間いても、1 分あたりと 1 時間あたりの行数が上限以下、同じ住民の発言の間隔が下限以上。
6. **LLM がないとき・失敗したとき（共通）。** 生成器がないとき、住民は話さない。生成器が失敗した枠、検証に落ちた枠は、何も表示しない
   （その住民が黙った）。代わりの決まり文句は出ない。
   - 独立したテスト: 失敗する生成器と、検証に落ちる 1 行（改行入り、長すぎる、表示できない文字、未来の語）を返す生成器で、発言が記録されない。
7. **抜けるときに見送られる（共通）。** 人間が「そろそろ落ちます」のように抜けることを告げると、部屋の住民が「おつかれー」と見送ることがある。
   通常の応答とは別枠で、知り合いほど見送りやすい。必ずではない。
   - 独立したテスト: 抜けることを告げる発言に、`sendoff` の枠が 0〜2 人分でき、通常の応答（`reply`）の枠はできない。
     関係のある住民の見送りの率が初対面より高い。抜けることを告げない発言には `sendoff` ができない。
8. **知り合いが出来事を話題にする（共通）。** 人間が掲示板に書き込んだり、その書き込みにレスが付いたりしたあと、部屋にその人の
   知り合いの住民がいると「さっき○○に書いてたね」のように話題にすることがある。必ずではない。
   - 独立したテスト: 部屋にいる人の直近の書き込みの事象があるとき、関係のある住民に `news` の枠ができることがあり、
     関係のない住民にはできない。1 つの出来事につき多くとも 1 人。古い出来事（決めた時間より前）には枠ができない。
9. **入力中は割り込まない（絵理香K版）。** spec 016 と同じく、部屋の画面以外では発言の行は出ない。自分の発言は二重に出ない。
   - 独立したテスト: 自分の発言が `Poll` の出力に再び現れない。

## 5. 要件（FR）

### 共通の方針（ホストプログラムに依らない）

- **FR-001（発言の枠）**: 住民がチャット室で話す機会（枠）を、World が LLM を使わずに決定論的に決める。枠は
  `(局, 部屋, 話者, 時刻, 種類, きっかけ, 宛先)` を持ち、きっかけと話者などから求めた安定した鍵で識別する。
  枠の種類は共通の語彙とする。
  - `greet`（入室のあいさつ）: 自分が入ったとき、部屋に誰かいれば。
  - `welcome`（迎え）: 他の人（人間を含む）が入ったとき。1 回の入室につき多くとも 1 人。
  - `reply`（応答）: 他の人の発言に。1 発言につき多くとも 1 人。
  - `talk`（自発）: 部屋にいる間、住民ごとの頻度で。部屋に自分のほかに誰かいるときだけ。
  - `farewell`（退室のあいさつ）: 計画の退室の少し前に。
  - `sendoff`（見送り）: 他の人（人間を含む）が抜けることを告げる発言をしたとき。**通常の応答とは別枠**で、その発言には `reply` を作らない。
    1 発言につき多くとも 2 人。抜けることを告げる発言かは、共通の短い語の一覧で決める（LLM を使わない）。
  - `news`（出来事の話題）: 部屋にいる人の、直近の世界の出来事（掲示板への書き込み、その書き込みへのレス）を、その人の知り合い
    （関係が「以前にもやり取り」以上）の住民が話題にする。1 つの出来事につき多くとも 1 人。出来事は台帳（`InteractionEvent`）から読む。
  確率と間隔は、人物（`ReplyTendency`、`LurkerTendency`、`NewcomerOpenness`）、関係（spec 013 の分類）、ハンドルで呼ばれたかで決める。
  係数は架空の調整値であることをコードに書く。
- **FR-002（観測される間だけ）**: 枠を計算し本文を作るのは、人間がその部屋にいる区間の時刻だけ。きっかけ（入室・発言）もその区間のものだけを数える
  （`news` のきっかけの出来事は部屋の外の世界の事実なので例外とし、枠の時刻より決めた時間内のものだけを数える）。
  人間がいる区間の外の枠は計算しない（観測されない事実として作らない）。人間がいることで、住民の入退室（spec 016 の計画）は変わらない。
- **FR-003（本文の生成）**: 枠の本文を、`llm` の新しい狭いインターフェース（チャットの 1 行の生成）で作る。入力は材料として渡す。
  - 話者の人物像と文体（spec 013 の `personaSummary` と同じもの）
  - 枠の種類、宛先のハンドル、宛先との関係の分類
  - 部屋にいる人のハンドル
  - 話者が入室してから部屋で記録された発言のうち直近のもの
  - 世界の日時、局の名前、部屋の番号
  - `news` では出来事の要約（誰が、どの掲示板に、どの題で書いたか、誰にレスが付いたか。本文は渡さない）
  出力は JSON スキーマで 1 行の本文だけとする。世界の基準の日付より後の知識・製品・語を使わないことと、その時代のパソコン通信の
  チャットの口調（顔文字は使いすぎない）を、既存の時代の枠（`DiegeticWorldFrame` など）で伝える。
- **FR-004（検証）**: 1 行（改行なし）、空でない、共通の上限の幅以内、Shift_JIS で表せる、ハンドルの前置き（`HANDLE:`）がない、
  既存の未来・メタの語の検査（`forbiddenFutureMetaTerm`）を通る。落ちたら記録せず、その枠は黙ったことにする。再試行は 1 回まで。
- **FR-005（上限）**: 1 部屋の住民の発言について、行と行の最短の間隔、1 分あたりと 1 時間あたりの行数の上限、同じ住民の最短の間隔を置く。
  局ごとの LLM の呼び出しの同時実行数にも上限を置く。上限を超える枠は時刻順に後ろから捨てる（黙る）。値は架空の調整値で、コードに書く。
  応答に応答する連鎖の深さにも上限を置く。
- **FR-006（時刻と記録）**: 枠の時刻より前に本文の生成を始め、間に合えば枠の時刻、間に合わなければ記録した時点の世界時刻を、発言の時刻にする。
  発言の時刻は記録の時点より過去にならない（すでに表示した範囲に後から割り込まない）。古くなった枠（決めた時間を過ぎても本文がない）は捨てる。
  記録は spec 016 の `ChatUtterance` に、枠の鍵と、応じた発言の ID を加えて行い、台帳（`chat_utterance`、`npc_world_selected`、
  応じた発言の台帳の事象を `RespondsToEventID`）に記録する。同じ枠は 2 回記録しない。記録した発言は変えない。
- **FR-007（共通の出力）**: spec 016 の `ChatEvents` が、入退室に加えて、部屋で記録された発言（人間のものも住民のものも）を
  時刻順に返す。ホストプログラムは、この呼び出しだけで部屋の出来事を得る。`ChatEvents` の呼び出しが、FR-002 の観測と、
  時刻の近い枠の生成の開始を兼ねる。生成は呼び出しを待たせない（非同期）。
- **FR-008（有効化）**: 生成器は Store の設定で与える。`cmd/server` は LLM の設定があるとき、既存の構造化出力の生成器を与える。
  生成器がないとき、住民は話さない（入退室は spec 016 のまま）。
- **FR-009（記録の検査）**: 住民の発言を記録したとき、既存の生成内容のログと同じ条件（`DEBUG_LOG_GENERATED_CONTENT` と局の
  `debug.content_log`）で、`Chat generated content:` の JSON の行をログに出す（枠の種類、話者、宛先、きっかけ、本文、所要時間）。
  失敗と検証の不合格は、条件によらず短いエラーの行を出す。`docs/DEBUG_INSPECTION.md` に書く。

### 絵理香K版での具現化

- **FR-010（発言の行）**: 部屋にいる人間に、`ChatEvents` の発言を `padRunes(HANDLE, 8) + ":" + 本文` の行で出す（spec 016 FR-008 の形）。
  入退室の行と時刻順に混ぜる。自分の発言は、入力したときにすでに出しているので出さない。
- **FR-011（文書）**: `docs/WORLD_SIMULATION.md` に発言の枠の方針、`docs/LLM_POLICY.md` にチャットの 1 行の生成の位置づけ、
  `docs/host-programs/erika-k.md` に発言の表示を書く。住民の会話の頻度・上限は Fictional reconstruction と書く。

## 6. 成功基準（SC）

- SC-001: §4 の各ストーリーの独立したテストが通る。
- SC-002: 絵理香K版の画面の金型（`screens_golden.txt`、`boards_golden.json`）と人物生成の金型が 1 バイトも変わらない。
- SC-003: LLM の設定がなくても、すべて動作する（住民はチャット室に入らず、話さない）。テストは実際の LLM を呼ばない。
- SC-004: 共通の層（`world`、`worldrepo`、`llm` のチャットの部分）に、絵理香K版の画面の文字列が現れない。
- SC-005: `go -C apps/server test ./... -count=1`、`go -C apps/server vet ./...`、`go -C apps/server test -race ./internal/worldrepo ./internal/ws` が通る。

## 7. 不変条件

- 誰がいつ何に応じて話すかは World が決める。LLM は本文だけを作り、話者・宛先・時刻・きっかけを変えない。
- 人間の発言 1 つに応じる住民は多くとも 1 人。応じないことがある。見送り（`sendoff`）は別枠で多くとも 2 人、出来事の話題（`news`）は 1 つの出来事につき多くとも 1 人。
- 出来事の話題は、World が選んだ出来事の要約だけを材料にする。LLM が出来事を作らない。
- 本文は、人間がその部屋にいる時刻の枠についてだけ作る。
- 記録した発言は書き換えない。表示済みの時刻の範囲に、後から発言を割り込ませない。
- 失敗は沈黙になる。決まり文句の代わりの本文を作らない。
- 住民の入退室（spec 016 の計画）は、本仕様の発言で変わらない。

## 8. スコープ外

- 回線宛メッセージ（電報）への返信、住民から人間へのメッセージ（spec 018）。
- チャットの発言による関係（`RelationshipEdge`）の更新。チャットの発言を行動の記憶（spec 011/012）の検索対象にすること。
- 通話中の書き込み・レス、掲示板での反応の選択（spec 008）。
- 生成の追跡（`/api/debug/bbs/generation-trace`）へのチャットの追加。
- 人間が部屋に入る前の会話の再現（入室時の過去ログの表示）。
- 絵理香K版以外のホストプログラムでの具現化、会議室（JUNK）、絵理香K版の `BELL ON/OFF`・`S`・`P`。
- 他の人間の利用者（複数の人間が同じ世界にいる場合）。
- 既存の書き込みの日時の修正。
