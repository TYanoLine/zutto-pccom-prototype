# Spec 014: 80桁端末環境に即した記事レイアウトと改行指針 (terminal-line-wrap-and-layout)

## 1. 概要 (Overview)

本仕様は、1996 年当時の PC-9801 / DOS/V / VT100 端末（画面幅：半角80桁 / 全角40文字、縦25行）における BBS 記事本文の表示体験を忠実に再現するため、記事本文生成時の改行および1行文字数のレイアウトを改善する改修である。

現代の Web・スマートフォンのように「改行なしの 100〜150 文字以上の長文段落を画面端（全角40文字目）で機械的に自動折り返しさせ、単語や文節が途中でちぎれる」不自然さを解消し、当時のパソコン通信のネチケット・執筆作法に則った「全角30〜35文字前後での適度な文節・句点改行」を実現する。

---

## 2. 背景と課題 (Background & Problem)

1. **画面端での機械的強制折り返し（単語ブツ切り）の発生**:
   - 現在の LLM は段落内に改行コード（`\r\n`）を入れず、1行に 100〜150 文字以上の長文を一塊として出力している。
   - ターミナル（全角40文字 / 半角80桁）にこれを流すと、全角40文字目で問答無用に自動折り返しが発生し、「急いでク／リアする」「思って／ます。」のように単語の真ん中や助詞の途中、禁則文字（行頭の「。」など）が画面端で分断されて非常に読みづらくなっている。
2. **1996 年当時の実際の執筆・レイアウト文化との乖離**:
   - 当時のパソコン通信（KTX、まいと～く、WTERM、VZ Editor、MIFES など）では、画面幅（40文字）にぶつかって単語がちぎれるのを防ぐため、**全角30〜35文字前後（句点「。」や文節の区切り）で人間が適度にEnter（改行）を入れる**、あるいはエディタのハードラップ（全角35文字前後）で改行コードを埋め込んでから投稿するのが常識的なマナーであった。
   - 逆に、現代のスマホSNSやケータイ小説のように「1行15文字程度でポエムのように細かく改行する」のも、縦25行しかない当時の画面では「無駄に縦長になってスクロールの手間や通信時間の無駄になる」として嫌われていた。
3. **必要な改善**:
   - プロンプトの文体指針に、当時の端末幅（全角40文字）を意識したレイアウト指針（1行30〜35文字目安、句点や文節での自然な改行、極端な短文改行やノーブレイク長文の回避）を追加する。
   - 本文生成時のサンプリングテストにおいて、生成された各行が全角40文字以内に概ね収まり、自然な文節で改行されていることを検証する。

---

## 3. 要件 (Requirements)

### 機能要件 (Functional Requirements)

- **FR-001 (プロンプトへの1行文字数・改行指針の追加)**:
  - `apps/server/internal/llm/board_post_prompt.go` および `board_post_freeform.go` の文体指針に、以下の改行・レイアウト指示を追加する：
    - 「1行の長さは全角30〜35文字程度を目安とし、句点（。）やキリの良い文節で適度に改行を入れてください。」
    - 「改行を入れずに画面端（全角40文字）で機械的に折り返されるような長い1行や、逆に15文字程度の極端に短い改行の多用は避けてください。」
- **FR-002 (サンプリング検証ハーネスでの行長・改行レイアウト検証)**:
  - `apps/server/internal/worldrepo/materialize_sampling_test.go` に、生成された記事本文の各行の長さ（表示セル幅 / 全角文字数換算）が当時の80桁端末に即した自然な範囲（極端なノーブレイク行や過剰な細切れ改行がないこと）であることを検証するシナリオを追加する。

---

## 4. 制約・境界条件 (Constraints)

- **金型テストの完全保全**:
  - `TestPopulationMatchesGolden` (人物生成金型) は 1 バイトも変えない。
  - `TestGoldenBoardTableShape` (画面出力金型) は 1 バイトも変えない。
- **全パッケージテストと静的解析の通過**:
  - `go -C apps/server test ./... -count=1` が全25パッケージ PASS すること。
  - `go -C apps/server vet ./...` がエラー 0 件であること。
- **改行コード**:
  - すべてのファイルは LF 改行で保存する。
