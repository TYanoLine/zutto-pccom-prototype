# 検証ガイド: BBS本文の人物別具体化

## 前提

Go 1.23 と `apps/server` の依存関係を用意する。共有記事具体化エンジンを通常ホストの閲覧と隔離 Lab の両方から呼び出せることを確認する。Lab は実験用データを使うため、検証環境で実施する。

## 自動検証

リポジトリの `apps/server` で実行する。

```powershell
go test ./internal/worldrepo ./internal/llm ./internal/hostprogram/erikak
```

人物履歴の時系列・本人限定・同一スレッド除外・上限、Detail の0〜2件とメタデータ拒否、件名保持、Erika-K アペンド失敗を確認する。加えて `ArticleDetailsMaterialized` のスナップショット保存・復元、正常0件、planner 不在、生成・検証・保存失敗、再閲覧・再起動、同時閲覧、本文済み旧記事の非再処理を確認する。

## 本文閲覧

1. 通常のホスト閲覧経路で本文未確定の記事を選び、件名を記録する。
2. 本文を読み、記事ローカル詳細と文章を確認する。
3. 再閲覧して件名、本文、詳細が一致することを確認する。
4. 複数返信の記事で意味の重複、本人と他人の経験の混同、アペンド表示を確認する。
5. 同じ共有処理を通常閲覧と Lab の隔離コピーから実行し、Detail 入力・完了状態・本文生成の成否規則が入口で変わらないことを確認する。

閲覧の振る舞いは [contracts/article-body-read.md](contracts/article-body-read.md)、保存境界は [data-model.md](data-model.md) を参照。詳細0件を返すケースを用意し、`ArticleDetailsMaterialized=true` が保存・復元されて再提案されないことを確認する。planner の生成・検証・保存失敗では本文 renderer が呼ばれず、完了状態が `false` のまま再試行可能であることも確認する。

## 品質サンプリング

既存 Lab の起動・結果取得は `docs/MATERIALIZATION_LAB.md` に従う。Lab は通常閲覧と同じ共有具体化処理を隔離データ上で実行する。`/poc/materialization-lab-viewer` で会話として先に読み、必要なときだけ診断表示を使う。`status=completed` のほか、`runtime_state`、`failures`、`empty_post_ids`、`body_count` を確認する。通常閲覧と Lab の入口で同じ記事条件を与えた際、選択規則・検証・保存の挙動が一致することも確認する。

| 単位 | 記録内容 |
| --- | --- |
| 実行 | ジョブ ID、対象コミット、世界日時、設定、モデル、完了・失敗数 |
| スレッド | 板、件名、返信数、先行返信の意味的反復 |
| 記事 | 具体的命題、短い反応の妥当性、一人称事実の根拠、未来漏洩、1996年境界、文体・背景の反復 |
| 問題 | 記事 ID、実際の文面、期待する境界、記事意図・局所詳細・本文のどこに原因があるか |

通常閲覧と Lab の双方で、同じ共有エンジンが処理した複数返信スレッドと抽象件名の記事を、確認できる範囲でレビューする。SDD の20〜30本のスレッドと仕様の20件の記事は標本が十分な場合の目安であり、最低件数や完了条件ではない。標本が少ない場合は実数と理由を記録する。Lab は標本と再現性を補うが、通常世界に一定数の返信があるとは仮定しない。自然さの未測定の数値閾値は設けない。

## 完了判定

自動テスト結果、0件・保存失敗・再閲覧の確認結果、通常閲覧と Lab の共有エンジン利用、品質標本の判定、未確認事項を記録する。
