# 記事本文の閲覧契約

対象は既存ホストの閲覧コマンドと内部の `WaitForArticleBody` に相当する観察境界。通常閲覧と開発用直接確認では同じ共有記事具体化処理を使い、呼び出し元によって本文・詳細の選択規則を変えない。新しい公開 API は設けない。

## 入力

確定済みのホスト、板、記事 ID、投稿者、世界日時、記事意図、返信先。人物事実は投稿時点で有効なもの、本人の先行発言は最大6件を入力にする。

## 成功時

1. 初回閲覧で確定した本文を後続閲覧でも返す。
2. 件名と返信関係を維持する。Erika-K のアペンドは独立件名を付けない。
3. 未来の人物事実、別人の経験、無関係なスレッドを本文へ混入させない。
4. 局所詳細があれば自然に反映する。0件でも短い反応として成立できる。
5. スレッド先行本文が必要なら先に確定し、同時閲覧でも結果を共有する。
6. 正常な0件応答は完了状態とともに保存し、再閲覧・再起動後に再提案しない。Detail の生成失敗は0件とみなさず、本文を確定しない。
7. 本文未確定の記事は、通常閲覧・開発用直接確認のどちらでも同じ Detail 入力、検証、保存規則を通る。

## 失敗時

- 詳細・本文生成は既存の期限内で1回再試行する。
- Detail planner が未構成、生成・検証に失敗、または完了状態を記事へ保存できない場合は本文 renderer を呼ばない。
- 最終失敗でも確定済み件名と世界事実を維持し、ホスト・板・記事 ID と原因を運用記録へ残す。
- Erika-K のアペンド失敗は `(アペンドの読み込みに失敗しました)` と表示する。
- 詳細または本文の保存を確認できない場合、未保存の生成結果を成功として返さない。

## 評価用の契約

通常閲覧とGoテストで共有記事具体化処理の結果を検証する。退役したLab APIへの依存はない。
