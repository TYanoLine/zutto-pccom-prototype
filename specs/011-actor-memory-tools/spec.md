# Spec: エージェント記憶想起ツールと非同期マイクロバッチ埋め込み（Actor Memory Tools）

**Spec ID**: 011-actor-memory-tools  
**Status**: Draft  
**Depends on**: 010-interaction-ledger（台帳・関係エッジ）、SDD-005 P3 の一部

## 背景

`llm/tools.go` に 6 つの標準ツール定義（`StandardActorTools`）、`ToolRegistry`、`MaxToolCallsPerTurn = 1` の方針が既にある。
`llm/embedding.go` に埋め込みクライアント（`text-embedding-3-small`）とコサイン類似度がある。
Spec 010 で、掲示板の投稿が `InteractionEvent` として台帳に追記され、返信が `RelationshipEdge` に反映されるようになった。

しかし現状は次のとおりで、ツールは**定義だけ**で何にもつながっていない:

1. ツールを実行する実体（`ActorScopedToolExecutor` の実装）がない。`MockToolExecutor` しかない。
2. 埋め込みは呼び出せるが、記事を保存したときにベクトルを作って保持する仕組みがない。
3. 「ツール定義を提示 → モデルがツールを要求 → 結果を返して最終出力」を最大 1 往復で回す共通の制御がない。

本 spec は、これらを**生成 LLM を使わずに**つなぐ。具体的には、行為者の観測範囲に閉じたツール実行器、
非同期マイクロバッチ埋め込みインデックス、最大 1 往復のオーケストレーターを作る。
実際の本文生成（BBS・チャット）への組み込みは本 spec のスコープ外（後続 spec）。

## 設計の原則

- **ツールの内部処理に生成 LLM を使わない。** 直接参照はメモリ上の取得、曖昧検索は埋め込みのベクトル検索で完結する。
- **行為者の観測範囲に閉じる。** ツールは呼び出した行為者（`actorID`）が観測できる情報だけを返す。他人の私信や、まだ観測していない出来事を返さない。
- **保存処理を遅くしない。** 埋め込みは保存の後ろで非同期に作る。API の失敗や遅延が、投稿の保存・表示を止めない。
- **AI なしで動く。** 埋め込みクライアントが未設定でも、投稿の保存・直接参照系ツールは動く（検索ツールだけが「利用不可」を返す）。
- **台帳・投稿が真実。** 埋め込みインデックスは派生キャッシュであり、失われても台帳から再構築できる。

## ユーザーストーリー

### US1: 自分の投稿・スレッド・やり取りを思い出せる（Priority: P1）

行為者が `get_my_recent_posts`・`get_thread_context`・`get_interaction_history_with`・`get_my_profile_facts` を呼ぶと、
世界の保存データから正しい内容が、新しい順・件数上限つきで返る。

**Independent Test**: 固定の投稿・台帳・人物事実を入れたストアに対して各ツールを実行し、期待した項目と順序が返ること。

### US2: 話題から過去の観測を検索できる（Priority: P1）

`search_my_observed_events(query)` が、表記揺れのある問い合わせでも、行為者が観測した投稿から関連の高い順に返す。

**Independent Test**: モック埋め込みで、似たベクトルの投稿が上位に来る。観測範囲外の投稿は、類似度が高くても返らない。

### US3: 埋め込みは保存を待たせず、まとめて作られる（Priority: P1）

投稿の保存は埋め込みの完了を待たない。バックグラウンドのワーカーが、10 件たまるか 200ms 経つたびに 1 回の API 呼び出しでまとめて埋め込む。

**Independent Test**: 埋め込み呼び出しがブロックしていても保存が即座に返る。25 件の投入で API 呼び出しが 3 回以下になる。失敗した場合も保存は成功し、ワーカーは止まらない。

### US4: ツール呼び出しは最大 1 往復で終わる（Priority: P1）

オーケストレーターが、ツール定義つきで 1 回目を呼び、ツール要求があれば実行して、ツール定義なしの 2 回目で最終出力を得る。

**Independent Test**: ツール要求なし → モデル呼び出し 1 回。ツール要求あり → 2 回。モデルが 2 回目にもツールを要求しても、3 回目は呼ばず、`ErrNoFinalText` を返す。1 回目に複数のツール要求があっても、実行するのは先頭の 1 件だけ。

### US5: LLM を呼ばない（Priority: P1）

ツールの実行と埋め込みインデックスの更新で、生成 LLM の呼び出しが 0 回である。

## 要件

- **FR-001（ツール実行器）**: `ActorScopedToolExecutor` を実装する実体を、新パッケージ `actormemory` に置く。`StandardActorTools` の 6 つすべてに応答する。
- **FR-002（観測範囲）**: 返す投稿・イベントは、(a) 呼び出した行為者の局で公開された板のもの、または (b) 台帳イベントの `Actor` か `AddressedTo` に行為者が含まれるもの、に限る。他の局のデータは返さない。
- **FR-003（件数）**: `limit` は 1〜5、省略時 3。範囲外は丸める。
- **FR-004（本文の抜粋）**: 本文は先頭 160 文字（ルーン単位）に切る。
- **FR-005（open loops）**: 未決事項の保存層は本 spec では作らない。`get_my_open_loops` は「未決事項はありません」を成功として返す。
- **FR-006（対応チャネル）**: 台帳に存在するチャネル（現状は `board_root`・`board_reply`）だけを扱う。`chat`・`mail` の指定は空の結果を返す（エラーにしない）。
- **FR-007（埋め込みインデックス）**: `actormemory.Index` は、`Enqueue(item)` で非同期に投入し、バックグラウンドのワーカーが「10 件または 200ms」でバッチ化して `EmbeddingClient.Embed` を呼ぶ。
- **FR-008（冪等）**: 同じ `EventID` の再投入は、ベクトルを二重に作らない。
- **FR-009（検索）**: 検索は問い合わせ文を 1 回埋め込み、観測範囲でフィルタしたうえでコサイン類似度の降順に返す。類似度が 0 以下のものは返さない。
- **FR-010（縮退）**: 埋め込みクライアントが nil、または埋め込みが失敗したとき、`search_my_observed_events` は `IsError` ではなく「検索は現在利用できません」という通常の結果を返す。直接参照系ツールは影響を受けない。
- **FR-011（オーケストレーター）**: `llm.RunToolTurn` は、`MaxToolCallsPerTurn` に従い、最大 1 往復で終了する。
- **FR-012（配線）**: `worldrepo.Repository` は、任意の `PostIndexer` を持てる。設定されていれば `AddPost` の後で非同期投入する。nil なら何もしない。既存の挙動と出力は変わらない。
- **FR-013（LLM 非依存）**: FR-001〜FR-010 は生成 LLM を呼ばない。

## 成功基準

- **SC-001**: 6 つのツールが、固定データに対して期待どおりの結果を返す。
- **SC-002**: 観測範囲外のデータが、どのツールからも返らない。
- **SC-003**: 保存のレイテンシが、埋め込み API の遅延に影響されない。
- **SC-004**: ツール使用時のモデル呼び出しが最大 2 回、不使用時は 1 回。
- **SC-005**: 既存の金型（`population_golden_test.go`、画面金型）が 1 バイトも変わらない。
- **SC-006**: `go -C apps/server test ./...` が通る。

## スコープ外

- BBS 本文生成・チャット発言生成への実際の組み込み（プロンプト変更、`bbs_render_context` の置き換え）。
- Azure OpenAI のツール呼び出し API（function calling）へのアダプター。本 spec は、モデル側を抽象インターフェースで受ける。
- 未決事項（`OpenLoop`）の保存・導出。メール・チャットの保存と台帳追記。
- 埋め込みベクトルの永続化（再起動時は台帳から再構築する前提。本 spec は構築の入口まで）。
- 既存の人物生成・画面出力の変更。
