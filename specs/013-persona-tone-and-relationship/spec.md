# Spec 013: ペルソナ個性パラメータと関係性の反映によるBBS本文文体の生動化 (persona-tone-and-relationship)

## 1. 概要 (Overview)

本仕様は、1996 年当時の草の根パソコン通信世界における BBS 記事本文生成において、各ペルソナの個性パラメータ（年齢、性別、職業、文体特徴、議論性など）および住民同士の関係性（初対面か、親しい常連仲間か）を本文生成プロンプトに有機的に結合し、現代 LLM 特有の「ビジネスメール・メルカリのような過度にかしこまった敬語」を打破して、当時の趣味サークルや部室のような自然な体温・生っぽさを持つ文章を生成するための改修である。

---

## 2. 背景と課題 (Background & Problem)

1. **「かしこまりすぎ」の問題**:
   - 現代の大規模言語モデルは「丁寧なアシスタント」としての基本訓練バイアスが強いため、指示がニュートラルだと自動的に「です・ます」で整ったビジネスメール調や定型挨拶（「クリアおめでとうございます」「ご相談させてください」「よろしくお願いします」）を量産してしまう。
   - 1996 年当時の草の根 BBS（特に GAME 板や雑談板）は、会社や公の場ではなく「趣味のサークルや大学の部室、深夜の溜まり場」に近い空気感であり、最低限のネチケットを守りつつも、感情やテンションが直に出るカジュアルな口語（「〜ですねー」「〜かも」「おおっ」）や感情表現（`(笑)`、`(^^;`、`(爆)` 等）が飛び交っていた。
2. **ペルソナ個性パラメータの活用不足**:
   - `world.Persona` には `Age`, `Gender`, `Occupation`, `WritingStyle`, `Argumentativeness` などの豊かな個性が保持されているが、プロンプトには `age=24; gender=male; writing=気さくな口調; argumentative=0.80` というキーバリュー文字列のまま渡されており、LLM からは単なるメタデータとみなされ、実際の執筆トーンに反映されにくかった。
3. **住民同士の関係性の欠如**:
   - 相手が「初対面」なのか「普段から掲示板でやり取りしている馴染みの常連仲間」なのかによって、本来の会話の距離感は大きく異なる。
   - Spec 010 で関係性台帳（`RelationshipEdge`）が実装されたが、本文生成プロンプトには相手との関係性情報が渡されていなかった。

---

## 3. 要件 (Requirements)

### 機能要件 (Functional Requirements)

- **FR-001 (ペルソナ個性の自然言語プロファイル化)**:
  - `llm_materializer.go` の `personaSummary` を改修し、機械的なキーバリュー文字列ではなく、LLM が演じやすい自然な人物像・文体指針（例:「24歳・会社員・男性。気さくで親しみやすい口調。(笑)を時々使う。ゲームの話題には熱が入る」）に整形してプロンプトへ渡す。
  - `Argumentativeness` や `WritingStyle` を文体指示として反映する。
- **FR-002 (関係性データの取得とプロンプト注入)**:
  - 返信記事（`ParentPost` が存在する場合）の生成時、投稿者と返信先著者の間の `RelationshipEdge` を `world.Store.GetRelationship` から取得する。
  -やり取り回数（`BoardReplyCount`）に基づき、以下の関係性文脈をプロンプトに注入する：
    - 初対面 (`BoardReplyCount == 0`): 「相手とは初めてのやり取り（初対面）です。最低限のネチケットを守りつつ、趣味の仲間として親しみやすく接します。」
    - 馴染みの常連 (`BoardReplyCount >= 2`): 「相手とは以前から掲示板で何度もやり取りしている気心の知れた常連仲間です。堅苦しい挨拶は抜きにして、サークルや部室のようなフランクなノリで話します。」
    - 過去にやり取りあり (`BoardReplyCount == 1`): 「相手とは以前にもやり取りしたことがある仲間です。」
- **FR-003 (1996年当時の草の根BBS文体指針の追加)**:
  - `BuildBoardPostPrompt` および `buildFreeformBoardPostPrompt` において、ビジネスメール調の定型敬語の連打を抑制し、当時の趣味系 BBS らしい生きた会話口調（「〜ですねー」「〜かも」「おおっ」）や感情表現（`(笑)`、`(^^;`、`(爆)` 等）を人物の個性に沿って交える文体指針を追加する。
- **FR-004 (サンプリング検証ハーネス)**:
  - 常連同士のフランクなやり取り、初対面の適度な礼儀正しさと親しみやすさ、および異なる個性（オタク口調、落ち着いた社会人、勢いのある短文等）が自然に出力されることを単体テストで実証する。

---

## 4. 制約・境界条件 (Constraints)

- **金型テストの完全保全**:
  - `TestPopulationMatchesGolden` (人物生成金型) は 1 バイトも変えない。
  - `TestGoldenBoardTableShape` (画面出力金型) は 1 バイトも変えない。
- **全パッケージテストと静的解析の通過**:
  - `go -C apps/server test ./... -count=1` が全パッケージ PASS すること。
  - `go -C apps/server vet ./...` がエラー 0 件であること。
- **改行コード**:
  - すべてのファイルは LF 改行で保存する。
