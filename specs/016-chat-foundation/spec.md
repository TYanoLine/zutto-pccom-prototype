# Spec 016: 非同期出力、通話の中の行動、絵理香K版の電報・チャット画面 (chat-foundation)

## 1. 概要

接続中の住民とチャットするための土台を作る。本仕様では、住民は話さない（発言は spec 017）。

1. **非同期出力。** 人間が何も入力していなくても、ホストプログラムが端末に文字を出せるようにする
   （チャットの他人の発言、入退室、電報の着信）。
2. **通話の中の行動。** spec 015 で決まった住民の通話ごとに、その通話の中で、いつ電報・チャットのメニューにいて、
   いつどのチャット室にいるかを World が決定論的に決める。WHO の状態欄（`idle` / `CALL` / `CHAT` など）に使う。
3. **絵理香K版の電報・チャット画面。** 1996 年の接続記録の形で作り直す。人間はチャット室に入れ、住民の入退室が
   時間とともに表示される。人間は住民に電報を送れる（住民は返信しない）。

## 2. 背景と課題

1. **端末への出力が 1 行ごとの応答だけ。** `ws/session.go` は 1 行を受け取るたびに `Runtime.HandleLine` の結果を 1 回送る。
   入力を待たずに文字を送る経路は、CONNECT 直後の `Welcome()` だけ（`ws/session.go:178-184`）。
   チャットでは、他人の発言や入退室が、人間の入力と無関係に届く。
2. **住民が通話の中で何をしているかがない。** `world.PresenceSession`（`world/presence.go:19-27`）は回線と時間だけを持つ。
3. **電報・チャットがスタブ。** 絵理香K版の `renderChatMenu`（`erikak/runtime.go:876-883`）と `handleSimpleMenu` の
   `"chat"`（同 570-583）は、資料にない固定の画面で、部屋に入れず、`CALL` は送ったと表示するだけ。
4. **資料。** 東京 GARAKUTA-KoBo の 1996-04-30 の接続記録（`docs/research/erika-k-sources/garakuta_D-00078.html`）に、
   電報のメニュー、WHO、電報の送信と保留、チャットのメニュー、入退室、発言の形が残っている（§5 FR-005）。

## 3. 決定事項（2026-10-12、プロジェクトのスレッドで合意）

- 順番はチャットを先に作る。本仕様はその 1 つ目（画面と入退室、発言なし）。発言は spec 017、電報の返信と住民からの電報は spec 018。
- 人間が同じ部屋にいるときは、住民同士の会話も本文を作る（上限つき、spec 017）。
- **LLM の設定がないときは、住民はチャット室に入らない。** 部屋には人間だけがいる。WHO と BUSY（spec 015）は今のまま。
- 住民から人間への電報は入れる（関係のある住民だけ、まれに、spec 018）。

## 4. ユーザーストーリー

1. **チャット室に人がいる。** テレホタイムに電報・チャットのメニューへ行くと、WHO に `CHAT #0` の住民が見える。
   部屋 0 に入ると、自分の `## chat on  HANDLE ##` が出る（すでにいる人の一覧は出ない）。しばらくすると別の住民が入ってきて
   `## chat on  HANDLE ##` が BEL とともに出る。誰かが通話を終えると `## chat off HANDLE ##` が出る。
   - 独立したテスト: 決まった世界時刻と住民で、部屋 0 に入ってから世界時刻を進めると、入退室の行が時刻順に出る。
2. **同じ時刻の同じ事実。** WHO を 2 回見ても、同じ時刻なら同じ状態が出る。一度表示した状態は、後から住民を追加しても変わらない。
   - 独立したテスト: 観測した行動を保存したあと、住民を追加して再計算しても、保存した行動が残る。
3. **LLM がないと部屋は空。** LLM の設定がないとき、住民の状態に `CHAT` は出ず、部屋には人間だけがいる。
   - 独立したテスト: チャットを無効にした Store で、テレホタイムの住民の行動に `CHAT` が 1 つもない。
4. **電報。** 人間が `idle` の住民の回線番号に電報を送ると `#05 に電報を送りました。` と出る。`CHAT` の住民に送ると
   「チャットルームか会議室にちゃっかり入ってます。 CHAT終了後、電報を送ります。」と出る。空き回線には送れない。
   - 独立したテスト: 3 つの場合の出力と、電報が台帳に `telegram` として保存されること。
5. **入力中は割り込まない。** 記事を書いている途中や、電報の本文を入力している途中には、チャットの行も電報の着信も出ない。
   - 独立したテスト: 本文入力の状態では `Poll` が空を返し、メニューに戻ると溜まった分が出る。

## 5. 要件（FR）

- **FR-001（非同期出力）**: `hostprogram` に任意のインターフェース `AsyncOutput`（`Poll(now time.Time) string`）を追加する。
  `ws` は通話ごとに一定間隔（1 秒）で `Poll` を呼び、空でなければ `terminal` メッセージとして送る。`HandleLine` と `Poll` は
  同じ通話の中で同時に実行しない（通話ごとのロック）。切断中（再接続の猶予中）は `Poll` を呼ばない。
  再接続したら次の `Poll` で溜まった分が出る。何をいつ出すかはホストプログラムが決める。
- **FR-002（通話の中の行動）**: 住民の通話ごとに、通話の中の区間（`login` / `idle` / `CALL` / `CHAT #n`）を、
  `(局, 住民, 通話開始)` から決定論的に決める。LLM を使わない。係数は架空の調整値であることをコードに書く。
  チャット室に入るかは、生活類型と時刻（テレホ帯で多い）、部屋の定員、**その時点でその部屋にいる住民の数**で決める。
  人間がいることは、住民の行動を変えない。
- **FR-003（観測で確定する）**: WHO に表示した状態と、人間がいる部屋で表示した入退室は、保存して以後変えない。
  計算は保存を伴わない。保存は spec 015 の接続の保存と同じ単位（局ごとに直列化）で行う。
- **FR-004（チャットの有効化）**: Store の設定でチャット（住民がチャット室に入ること）を有効にする。`cmd/server` は
  LLM の設定（API キー）があるときだけ有効にする。無効のとき、FR-002 は `CHAT` の区間を作らない。
- **FR-005（絵理香K版の電報・チャット画面）**: 次を接続記録の形で作る。行の形とプロンプトは記録から写す。
  電報メニュー、`CALL> ->` のプロンプト、WHO の行（`#NN HANDLE 状態 アイコン 速度`、空き回線は `#NN ring`）、
  電報の送信（`電報をどうぞ。…` → `#NN に電報を送りました。` / 保留の文）、チャットのメニュー、入室の注意と
  `CHAT ON` の罫線、自分の入室の行、入退室（BEL 2 回と `## chat on  HANDLE ##` / `## chat off HANDLE ##`）、発言の行（`HANDLE  :本文`、
  ハンドルは 8 桁に詰める）、`..` で退室して `CHAT OFF`。
  - 局ごとに違いうるもの（電報メニューの見出しと項目の文面、部屋の数と定員、入室の注意文）は局の定義（YAML）に置く。
    定義にない部分は表示しない（ホストプログラムは既定の文面を持たない）。
  - 人間の発言は、部屋の行として表示し、台帳に `chat_utterance` として保存する（住民は応答しない）。
- **FR-006（電報）**: 人間は回線番号を指定して電報を送れる。相手が `CHAT` 中なら、チャット終了後に届いたことにする
  （届いた時刻は相手の `CHAT` 区間の終わり）。電報は保存し、台帳に `telegram` として記録する。住民は返信しない（spec 018）。
  `*`（全員宛）は本仕様では扱わない（`? COMMAND ERROR`）。
- **FR-007（文書と資料）**: `docs/host-programs/erika-k.md` に、電報・チャットの挙動と、Confirmed / Likely / 局固有の分類を書く。
  `docs/ARCHITECTURE.md` の「電報・チャットは固定のスタブ」の記述を更新する。

## 6. 成功基準（SC）

- SC-001: §4 の各ストーリーの独立したテストが通る。
- SC-002: 絵理香K版の画面の金型（`screens_golden.txt`、`boards_golden.json`）と人物生成の金型が 1 バイトも変わらない。
- SC-003: LLM の設定がなくても、すべて動作する（住民はチャット室に入らない）。
- SC-004: `go -C apps/server test ./... -count=1`、`go -C apps/server vet ./...`、`go -C apps/server test -race ./internal/ws` が通る。

## 7. 不変条件

- 住民の行動は World が決める。LLM は関わらない。人間がいることで住民の行動は変わらない。
- 観測された状態と入退室は書き換えない。
- 局固有の文面は局の定義に置く。
- 入力の途中に非同期の文字を割り込ませない。

## 8. スコープ外

- 住民の発言、住民同士の会話、LLM の呼び出し（spec 017）。
- 電報の返信、住民から人間への電報、全員宛の電報（spec 018）。
- 通話中の書き込み・レス（後続 spec、spec 008 と合わせる）。
- メインメニューの `WHO`（spec 015 の書式のまま）、`MEMB`、アクセス記録の固定の名前。
- `BELL ON/OFF`、`S`（受け取り状態の変更）、`P`（1 行プロフィール）。表示はするが、本仕様では `? COMMAND ERROR` を返す。
- 会議室（JUNK）。
- 絵理香K版以外のホストプログラム。
- 他の人間の利用者（複数の人間が同じ世界にいる場合）。
