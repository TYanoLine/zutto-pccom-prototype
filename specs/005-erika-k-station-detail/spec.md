# Spec: Erika-K の板構成と画面の文字列を局の定義（preset）に外部化する

**Spec ID**: 005-erika-k-station-detail（改訂 2: 画面の文字列を `texts` として局の定義に置く）
**Status**: Draft
**Depends on**: PR #294（局のフラグ）、spec 003（名前の中立化）、spec 004（住民の外部化）。いずれもマージ済み

## 背景

Erika-K（`apps/server/internal/hostprogram/erikak/runtime.go`）は、ホストプログラムとしての動作と、
HAKATA という 1 つの局の定義が、同じファイルに混ざっている。

- **局のデータ**が Go のソースに直接書かれている: 板の一覧 29 件（名前、概要、活動量、返信率、
  保持件数の上限、SYSOP 専用の指定、隠し板、別名）、未読マークの付く板、ログイン後の見出しと局のメッセージ、
  会員へのあいさつ。コメントにも「HAKATA station fiction」とある。
- **局名と罫線がコードに埋め込まれている**: メインメニューの見出し（`ＨＡＫＡＴＡ ＣＡＮＡＬ ＮＥＴ`、`絵理香Ｋ版`）、
  `WELCOME TO HAKATA CANAL NET` と `ERIKA-K` の見出し行、`■` の罫線、終了時の「また HAKATA CANAL NET で…」。
- 板の一覧は、グローバル変数 `boardTree` と、それを読むグローバル関数（`findNode`、`BoardByPath` など）になっている。
  別の Erika-K 局を追加すると、同じ板構成と同じ文言になってしまう。

局に固有の文字列と板構成は、すべて preset（YAML）の `detail:` に置く。ホストプログラム（Erika-K）は、
**定義された文字列を、そのまま出力する**ことと、動作（状態遷移、コマンド）だけを担当する。罫線を描く、見出しを組み立てる、
局名を差し込む、といった「文字列を作る処理」は、ホストに持たない。
**HAKATA の画面は、移行の前後で 1 バイトも変わってはならない**。

将来は、メインメニューなど Erika-K 共通の画面も、局の定義で既定から変えられるようにする予定である。
そのため、局の文字列は、場当たり的な項目ではなく、**名前の付いた画面の部品の表（`texts`）**として持つ。
部品を足すときは、キーを足すだけで、スキーマの作り直しが要らないようにする。

## ユーザーストーリー

### US1: 局の板構成と画面の文字列を preset に書ける（Priority: P1）

運営者として、Erika-K を使う局の preset に、板構成と、ログイン画面・メニューの見出し・終了のあいさつを書くだけで、
その局固有の板と文言で動くようにしたい。Erika-K のコードを書き換えずに、局を追加できるようにしたい。

**Independent Test**: テスト用に、別の板構成と別の文字列を与えた Erika-K の局が、その内容だけを表示する。
`detail.erika_k` の無い局は、板を持たず、`texts` の部品を何も出さない。

### US2: HAKATA の画面は移行前後で同一（Priority: P1）

運営者として、この変更で HAKATA の画面が変わらないことを、自動テストで確認したい。

**Independent Test**: 変更前のコードで記録した「板の表」と「画面の出力」が、変更後と完全に一致する。

## 要件

- **FR-001（スキーマ）**: preset に `detail.erika_k` を書ける（`plan.md` のスキーマ）。
  項目は、画面の文字列（`texts`）と板の一覧（`boards`）。
- **FR-002（対象プログラム）**: `detail.erika_k` は、`host.program` が `erika-k` の preset にだけ書ける。
  それ以外のプログラムの preset に書くと、読み込み時のエラーにする。
- **FR-003（データの受け渡し）**: Erika-K は、板構成と文字列を、`world.Store` の任意機能
  （`HostDetailStore`）から受け取る。`world.Host` には入れない（`Host` は `==` で比較される）。
  Erika-K のコードに、板の表、未読の指定、局の文字列を書かない。
- **FR-004（文字列はそのまま出力する）**: `texts` に定義された文字列を、ホストは**加工せずに出力する**。
  罫線を描かない、見出しを組み立てない、`Host.Name` や `Host.Software` を差し込まない、全角に変換しない。
  置換できるのは、実行時にしか決まらない `{handle}`（ログインした利用者のハンドル）だけ。
- **FR-005（完全な同一性）**: HAKATA の板の表（全項目）と、スクリプト化した操作の画面出力が、
  変更前のコードで記録した金型と、**1 バイトも違わず**一致する。
- **FR-006（デバッグ用の板の解決）**: グローバル関数 `BoardByPath` は、板の定義を引数に取る形にする。
  `cmd/server/main.go` のデバッグ用サンプルは、`HostDetailStore` から取得した定義を渡す。
- **FR-007（検証）**: preset の読み込み時に、`detail.erika_k` の構造を検証し、すべての問題を一度に報告する
  （`plan.md` の検証規則）。文字列の表示幅（各行 80 セル以下）は、`erikak` の検証関数で確認し、
  埋め込みの全 preset に対するテストで検査する。
- **FR-008（省略したキーは何も出さない）**: `texts` のキーを省略した局には、プログラムが既定の文面を持たず、
  **何も出力しない**。`detail.erika_k` が無い局でも `Runtime` は動作し、板は 0 件、`texts` の部品は何も出さない。
  `Runtime{}`（ゼロ値）でも panic しない。
- **FR-009（不変）**: 板構成と文字列は局の定義の一部であり、実行時に変更されず、
  永続化（スナップショット）にも含まれない。
- **FR-010（ドキュメント）**: `hostcatalog/README.md` に `detail.erika_k` の書式と検証規則、
  「省略したキーは何も出さない」ことを記載する。

## 成功基準

- **SC-001**: 変更前に生成した金型（板の表、画面の出力）を、**変更せずに**通る。
  金型は、**変更前の `main` のコードで生成したもの**であること（実装後のコードで生成した金型は、根拠にならない）。
- **SC-002**: `go -C apps/server test ./...` と `go -C apps/server vet ./...` が通る。
- **SC-003**: `apps/server/internal/hostprogram` のテスト以外の Go ファイルに、`hakata`
  （大文字小文字を区別しない）が残っていない。
- **SC-004**: 板を持たない Erika-K の局、`detail.erika_k` を持たない局、別の板構成と別の文字列を持つ局の
  テストがある。`texts` を省略した局が何も出さないことを確認するテストがある。

## スコープ外（変更しない）

- **メニューの表示の上書き**: メインメニューの項目と配置は、当面、プログラムの動作としてコードに残す。
  将来、`texts` にキーを足して、局の定義で上書きできるようにする（別 spec）。今回は、メインメニューの
  **見出しの 1 行（`main_menu_title`）**だけを局の文字列にする。
- **プロトタイプ用の固定画面**: `V`（アクセス記録）、`WHO`（回線表示）、`MEMB`（会員一覧）、メール一覧、
  ファイル一覧、`JUNK`。HAKATA の住民名（MARI、NORI など）や架空のファイル名が書かれているが、
  「prototype」と明記された仮の画面であり、世界のデータから作る形に置き換えるまで、コードに残す。
  SC-003 の `grep` には、これらの画面の記述が含まれない（`hakata` という文字列を含まないため）。
- 「前回アクセス」の行の文面と、日時（`96/08/25 23:41`）の固定値、「ご利用ありがとうございました。」の行。
  これらは Erika-K の標準の動作として、コードに残す。
- `Config`（機能と転送プロトコルの有効・無効）を preset から与えること。現状は `DefaultConfig()` のまま。
- `turbobbs`、汎用 BBS（`bbs`）のホストプログラム。
- `detail.welcome`（既存の、使われていない項目）。
- 板の活動量・返信率の調整。値は現状のまま移す。
- センターディレクトリ、テレホーダイ番号の既定値（Web 側）。
