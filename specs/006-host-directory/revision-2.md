# Revision 2: 生成局も電話帳に出す

**日付**: 2026-10-05（Part 2 の PR #320 のレビュー中）
**理由**: 運営者の方針変更。

> プリセット局は優先的に一覧に表示する。一方、LLM でのホスト定義作成は行い、一覧に表示する
> （今は繋がらなくてよい）。局定義に「リストに未掲載」とある局（`listed: false`）は、引き続き載せない
> （LLM でそのような局は、今は作らない）。

この改訂は、`spec.md`・`plan.md`・`tasks.md` の、**生成局を電話帳に出さない**前提の部分を置き換える。
Part 1（`GET /api/directory`、PR #319）は、そのまま有効（変更なし）。

## 置き換わる要件

| 元 | 改訂 2 |
|---|---|
| 質問 2「繋がらない生成局を、一覧に出すか」→「出さない」 | **出す**。ただし、プリセット局の後ろに並べる |
| FR-006（Web から、`fetchWorldCenters`、`getOrCreateWorldKey` などを削除） | **`fetchWorldCenters` と `getOrCreateWorldKey` は残す**（生成局の取得に必要）。削除するのは、`DEFAULT_CENTERS`、`loadCenters`、`saveCenters`、`RegisteredCenter.builtIn`、`CenterDirectoryPanel.tsx` |
| FR-006（Web は、`/api/world/bootstrap` を呼ばない） | **呼ぶ**（生成局の取得） |
| FR-007（旧キー `zutto.centers.v1`、`zutto.worldKey.v1` を削除） | **`zutto.centers.v1` だけを削除**する。`zutto.worldKey.v1` は、ブラウザごとの世界の鍵なので**残す**（消すと、LLM が 100 局を作り直す） |
| SC-003（`bootstrap` が `apps/web/src` に残らない） | `bootstrap` は残る（生成局の取得）。`DEFAULT_CENTERS`、`loadCenters`、`saveCenters`、`builtIn` は残らない |
| スコープ外「繋がらない生成局を、電話帳に出すこと」 | スコープに**含める**。繋がらない局は、今は区別せずに出す（呼ぶと `NO ANSWER`） |

## 追加の要件

- **FR-011（並び順）**: 電話帳は、プリセット局（`/api/directory`）を先頭に、生成局（`/api/world/bootstrap`）を後ろに並べる。
  電話番号が重なるときは、先のもの（プリセット局）を残す。生成局が、プリセット局を隠すことはない。
- **FR-012（取得の順序と失敗）**: 2 つの取得は、**並行して開始**する。プリセット局が取れた時点で、「読み込み完了」として電話帳を表示できる
  （生成局を待たない）。生成局は、取れたら後ろに追加する。**生成局の取得が失敗・遅延しても、プリセット局の電話帳は使える**
  （エラー表示にしない）。プリセット局の取得が失敗したときだけ、従来のエラーになる。
- **FR-013（`listed: false`）**: `listed: false` の局は、載せない（プリセット側は Part 1 のとおり。生成局には、そのような局は作られない）。

## 理由（設計の根拠）

- プリセット局は速く取れる（サーバの preset から導出）が、生成局は、初回の訪問で、LLM による局名の生成と保存を待つ
  （最大 120 秒）。**生成局を待たずに、HAKATA を先に表示する**ために、取得を分けて、プリセット局を先に確定させる。
- 世界の鍵（`zutto.worldKey.v1`）は、ブラウザごとの生成局を識別する。旧キーとして掃除すると、次の訪問で、
  生成が最初からやり直しになる。

## 検証

- 自動: `CenterDirectory.test.ts` に、`mergeCenters`（先頭の優先、重複、空、入力を変更しない）、`worldCentersEndpoint`、
  `getOrCreateWorldKey`（作成と保存、既存の鍵、不正な値の置き換え、保存先がブロックされた場合）、
  旧キーの掃除が世界の鍵を残すこと、を追加した。
- 手動（運用者）: ブラウザで、電話帳（メインメニューの `1`）を開き、
  1. HAKATA が先頭に表示される。
  2. しばらくして（初回は最大 2 分）、生成局が後ろに追加される（メインメニューの「登録センター」の局数が増える）。
  3. HAKATA に発信できる。
  4. `localStorage` に `zutto.worldKey.v1` が残っている（再訪問で、同じ生成局が出る）。

## 範囲外（別の変更として扱う）

- 生成局を呼べるようにすること（ホストの実体を作る）。
- 繋がらない局を、表示で区別すること。
- 読み込みに失敗したとき、端末の画面にエラーを表示すること。サーバが眠りから起動中のとき、自動で再試行すること。
  現状は、読み込み中の画面のまま止まることがある（以前からある挙動）。
