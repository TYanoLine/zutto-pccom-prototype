# Spec: 記事本文生成への記憶ツール結合とトーン調整（Actor Memory Integration）

**Spec ID**: 012-actor-memory-integration  
**Status**: Draft  
**Depends on**: 010-interaction-ledger（台帳・関係エッジ）、011-actor-memory-tools（ツール実行器・インデックス・オーケストレーター）

## 背景

Spec 010 で掲示板の投稿が追記専用の台帳（`InteractionEvent`）に記録され、関係エッジ（`RelationshipEdge`）が導出されるようになった。
Spec 011 でアクター記憶想起ツールの実行器（`actormemory.Executor`）、非同期マイクロバッチ埋め込みインデックス（`actormemory.Index`）、および最大 1 往復に制約されたオーケストレーター（`llm.RunToolTurn`）が単体モジュールとして完成した。

しかし現状は、サーバー起動部（`cmd/server/main.go`）および記事本文生成パイプライン（`worldrepo.LLMMaterializer`）にこれらが**配線（Wire-in）されていない**。そのため、実際にユーザーがアクセスしても記憶ツールが呼ばれず、住民の返信や発言に過去のやり取りが反映されない。

また、LLM に記憶ツールを与えたり過去の文脈を渡したりすると、**「指示に従おうとしすぎて、聞かれてもいないのに過去ログをわざとらしく引用する」「毎回『以前○○板でお話した通り〜』と不自然に前置きする」といったロボット的・過剰迎合的な不自然さ**が生じやすい。
1996 年のパソコン通信世界において、人間も NPC も対等な 1 参加者であり（人間を主人公にしない）、必要のない場面では過去ログを引かず、会話の流れで自然に必要な時だけさりげなく触れる（「あ、さっきの件ですか (^^;」程度）という自然な距離感を保つ必要がある。

本 spec は、Spec 011 の記憶ツールとインデクサを本文生成パイプラインおよびサーバー起動部に統合し、プロンプトのトーン調整とサンプリング検証を行う。

## 設計の原則

- **不自然な記憶連呼の抑制。** 記憶やツール結果は「事実の材料」であり、相手から尋ねられてもいないのに無理に過去ログを持ち出さない。会話の自然な流れを優先する。
- **人間を主人公・特別扱いにしない。** （`AGENTS.md` 原則）人間宛ての返信でも過剰な愛想や迎合をせず、対等なネット住民としての自然な距離感を保つ。
- **1996 年当時のネットスラング・マナーの遵守。** `(笑)`、`(^^;)`、`m(_ _)m`、適度な `>` 引用行など、時代に即した簡潔な文体を維持する。AI、データベース、記憶ツールの存在をメタに語らない。
- **保存処理・非同期性を阻害しない。** 投稿保存（`AddPost`）時のインデックス投入は非同期を維持し、保存レイテンシを増やさない。
- **AI / ツール未設定時も縮退稼働。** インデックスやモデルがツール呼び出しに対応していなくても、従来の本文生成がそのまま動作する。

## ユーザーストーリー

### US1: サーバー起動時に自動でインデクサが配線される（Priority: P1）

サーバー起動時（`cmd/server/main.go`）、設定された埋め込みクライアントを用いて `actormemory.Index` が生成され、リポジトリに `PostIndexer` として登録される。掲示板に投稿された記事は自動的に非同期でインデックスへ送られる。

**Independent Test**: `main.go` の初期化パスまたは結合テストで、`PostIndexer` がセットされ、`AddPost` された記事がインデックスに追加されること。

### US2: 返信・本文生成時に記憶ツールを介した想起ができる（Priority: P1）

記事本文の生成時、対象アクター（執筆者ペルソナ）に対して `StandardActorTools` の定義が提示され、モデルが過去の投稿やスレッド文脈を必要とした場合、`RunToolTurn` 経由でツールが実行されて本文に反映される。

**Independent Test**: 相手から以前の投稿について尋ねられたテストプロンプトにおいて、ツール要求が発生し、最大 1 往復でツール結果を踏まえた本文が生成されること。

### US3: 指示に従いすぎず、自然な距離感で返答する（Priority: P1）

初対面の会話や無関係な雑談ではツールを呼ばず、またツール結果や関係性があっても、聞かれていない過去の出来事をわざとらしく引用・連呼しない。

**Independent Test**: 初対面の投稿や一般的な雑談のプロンプトにおいて、ツール呼び出し回数が 0 回（初回呼び出しで即本文生成）であり、不自然な過去言及を含まないこと。

### US4: サンプリングによるトーンと挙動の検証・調整（Priority: P1）

サンプリングハーネスにより、代表的シナリオ（初対面、過去言及あり、無関係な新話題）で実際の生成文を比較検証し、不自然さがないことを確認できる。

## 要件

- **FR-001（サーバー配線）**: `cmd/server/main.go` で、埋め込みクライアントが利用可能な場合に `actormemory.NewIndex` を立ち上げ、`runtimeStore.SetPostIndexer` に登録する。
- **FR-002（マテリアライザーへの記憶統合）**: `worldrepo.LLMMaterializer`（または対応するレンダラー）に記憶実行器供給元（`actormemory.Executor`）を接続し、返信本文生成時に `RunToolTurn` を呼び出し可能にする。
- **FR-003（プロンプト規約）**: 本文生成プロンプトに以下の制約を組み込む：
  1. ツールは「直前の文脈で相手から過去の投稿や事実について具体的に問われた時」など、どうしても必要な時だけ呼ぶこと。通常の雑談や初対面では呼ばないこと。
  2. 過去のやり取りやツール結果を、聞かれてもいないのに唐突に自己紹介や昔話として持ち出さないこと。
  3. 1996 年のパソコン通信の対等な住民として、適度な `>` 引用と簡潔な文体、自然な距離感を保つこと。
- **FR-004（最大 1 往復制約の維持）**: 記憶ツールの呼び出しは `llm.RunToolTurn` のポリシーに従い最大 1 往復で完結し、2 回目のモデル呼び出しで必ず最終本文を出力する。
- **FR-005（フォールバック）**: ツール未設定時やエラー発生時、従来のダイレクト本文生成（ツールなし）にフォールバックして生成を継続する。
- **FR-006（サンプリングハーネス）**: 複数のシチュエーションで本文生成とツール呼び出しの有無を直接検証・記録できるテストまたは CLI スクリプトを用意する。

## 成功基準

- **SC-001**: `cmd/server/main.go` でインデクサが正しく初期化され、`AddPost` から検索までの経路が動く。
- **SC-002**: 過去の投稿に関する質問に対し、ツールが適切に呼ばれ、自然な返答本文が生成される。
- **SC-003**: 通常の雑談や初対面の投稿に対し、無駄なツール呼び出しや不自然な過去言及が発生しない。
- **SC-004**: 既存の金型テスト（`TestPopulationMatchesGolden`、`TestGoldenBoardTableShape`）が 1 バイトも変わらない。
- **SC-005**: `go -C apps/server test ./...` がすべて PASS する。
